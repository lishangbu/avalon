# 战斗框架实施与验收

核心模块 `avalon-combat` 仅使用 JDK，负责固定阶段、扩展契约、随机抽样、状态与资源变更结果。`avalon-battle` 注册 Avalon 的技能、特性、成长、AI、首领与训练规则，并承担持锁事务和游戏资产操作。现有野战、训练、单人首领及多人副本全部接入；本次保持现行玩法及数值，候选规则不默认为已实现。

## 已确认约束

- 核心接收隔离状态、指令与资源信息，返回新状态、事件和资源变更；不访问数据库或角色资产。
- 效果有序组合，状态显式声明叠加、刷新及移除；AI、首领和阶段钩子可注册。未知类型、重复注册、无效参数及引用拒绝启动。Java技能构造也显式使用效果列表，群攻识别与特性转换遍历完整列表，不依赖首项效果。
- 阶段顺序由核心控制；触发深度与事件数量有限，超限整回合回滚。完整回合为事务边界，不从半次技能中间恢复。
- 命令包含战斗、回合、状态修订与 UUID 请求号；相同请求重放原结果，改变载荷拒绝；多人仍检查成员归属和提交窗口。
- 全部元数据及调用方使用唯一新格式，不保留旧协议适配或存档导入。正式单人、多人存档与引擎副本统一严格解析，未知、旧属性和拼接JSON拒绝读取；首领私有状态由策略视图读写机制集合。上线前结束旧战局，已有角色资产保留。
- 重放记录使用 JSON Lines 文本文件，不入数据库；初始状态、规则配置、指令、外部输入、抽样、事件与结果可核对。数据库只保存恢复及幂等所需的正式状态与回执。
- 实现标识不匹配或记录缺失时拒绝精确重放，不保留旧执行器；历史重放使用对应提交构建的工具。
- 事务提交后写日志，失败告警而不撤销已提交战斗。日志挂载持久化目录；活动战斗不清理，已结束战斗默认保留30天，可导出与配置期限。
- 追加、状态变化和终局写入前核对整条文本历史的摘要及状态衔接，日志头须匹配当前战斗与实现；损坏记录拒绝续写，清理保留供排查。
- 新增和修改代码提供详细中文注释；每个公开顶层 Java 类型独立文件。

## 部署与离线核对

数据库迁移 `061-battle-framework.yaml` 在单人或多人活动战局存在时停止部署。发布前通过正式玩法结束战局；迁移清理旧回合回执并新增请求号、完整载荷与唯一约束，角色资产不受影响。

文本记录目录由 `avalon.battle.logs.directory` 配置，默认 `logs/battles`；部署文件挂载到 `/application/logs/battles`。保留期限由 `avalon.battle.logs.retention-days` 配置，默认30天，仅清理已结束且格式有效的记录。

离线入口为 `io.github.lishangbu.avalon.battle.replay.BattleReplayTool`，使用当前提交构建产物及其运行依赖组成类路径：传入 `validate` 校验配置与注册，传入 `replay <文件路径>` 核对完整文本记录。工具不启动服务或数据库；实现指纹不匹配时使用记录对应提交重新构建，不导入旧执行器。
