# 聊天与系统通知

本次访谈确认的首版包括玩家私聊、世界聊天、系统通知。区域和公会频道暂缓。全服公告仅由游戏事件自动生成，没有管理员手动发布接口。

## 玩家规则

私聊允许联系任何已有角色，支持离线留言。玩家可以拒收陌生人：只有已接受的好友关系允许发送，未接受的申请不算好友。拉黑阻止双方后续私聊，并隐藏本人所见的对方公共发言；不删除历史或好友关系，解除后恢复读取。

在「更多 → 好友」的已接受好友列表点击「私聊」，会展开全局聊天面板、选中该好友并聚焦输入框，无须重新输入角色名。快捷入口不会自动发送消息；重开同一好友保留未发送草稿，切换好友分别保留当前登录期间的草稿。战斗期间入口禁用，面板再次检查权限；好友申请列表没有此按钮。

首版只支持纯文本，每条1～500个Unicode码点。保存首尾去空白后的原文，允许换行和制表符，拒绝其他控制字符。玩家新消息使用共用禁词目录；历史不重新扫描，服务端系统文字不通过玩家禁词检测。前端插值转义正文，不执行HTML或脚本，不生成链接预览。

同角色跨频道共享发送限制：成功发送之间至少2秒，每分钟最多20条。状态持久化且发送受角色锁保护，不能通过刷新、换频道、多标签页或重启绕过。失败不占额度；同请求号、同内容成功重放不重复发送，同请求号改内容返回409。

私聊和个人系统通知长期保留；世界消息和全服公告只保留7天。历史每页50条，排他游标继续向更早历史加载。公开过期过滤即时生效，后台每秒按批物理删除（每批最多1000条）并级联清理对应已读凭证。没有撤回、编辑、全文搜索或附件。

私聊显示收件人的已读状态。接收消息、折叠面板、后台标签页不会自动已读；打开前台会话后按当前可见最新消息确认会话已读。系统频道支持本人已读，世界频道不显示已读回执。逐条凭证避免雪花生成顺序与事务提交顺序不同造成新消息误标已读。

## 战斗与界面

战外教学课程、生活活动与副本战间允许交流。战斗期间整个聊天面板、折叠入口和未读提示都隐藏，禁止查看或发送消息、确认已读、修改聊天设置。数据库照常接收和保留消息，战斗结束后恢复读取，未读保持。系统通知也不在战斗中展示。

后端正文与摘要接口检查真实战斗状态，写入口与开战共用角色锁。实时SSE仅发送固定ready/changed/heartbeat提示，不携带正文、角色名或消息编号，因此战斗期间流连接可以继续接收更新而不泄漏内容。开战/结束后提交事件唤醒同角色其他标签页核对权限。

游戏页面共用可折叠面板，按角色保存展开状态、频道、私聊对端与声音偏好。私聊声音默认关闭，可以开启；浏览器禁止自动播放时仍保留未读。消息、草稿、黑名单不持久化到浏览器；换号销毁旧连接与组件，拒绝旧身份迟到响应。

## 聊天布局与阅读交互

宽屏（至少 1380px）利用 480px 游戏界面右侧空白停靠聊天，不挤压游戏；窄桌面采用覆盖面板，手机展开后占满可视区域。面板通过 Teleport 挂载到 body，绕开 Ionic 固定定位包含块。移动端结合安全区与 visualViewport 高度调整输入区，真实软键盘仍需真机复核。

顶部固定世界、私聊、系统三个入口。私聊采用纵向会话列表和详情页，显示姓名及未读数；摘要接口不提供正文，因此不伪造最近消息预览。私聊为左右气泡，世界为紧凑消息流，系统为通知卡片，沿用游戏深浅主题。按日期分组，超过五分钟显示时间，私聊保留服务端已读状态。点击他人姓名打开操作菜单，拉黑须再次确认。

草稿及失败重试请求号按频道、私聊对端隔离，只保存在当前组件内存。发送等待服务端确认后才显示消息，失败保留草稿，重复提交受禁用状态及后端幂等约束保护。桌面 Enter 发送、Shift+Enter 换行；触屏回车保持换行，发送通过按钮，中文输入法组合确认不触发发送。

阅读历史时实时更新不强制滚到底部，显示新消息按钮；点击后滚到最新消息再确认已读。加载更早历史按滚动高度差保持位置，浏览器自动滚动锚定关闭以避免重复补偿。设置为独立子页，原历史 DOM 保留，返回后维持阅读位置。断线状态仅在顶部突出显示，重连继续补齐跨页积压。

## 可信系统事件

人物实际增加经验、正向金币到账、首次物品入库、首次伙伴获得、任务交付完成产生本人通知。经验以实际到账为准，满级截断不虚报；物品待领明确标出。业务回执重放不再发布首次事件。普通奖励不全服广播。

人物跨越10/20/30/40/50级里程碑自动生成全服公告；角色与里程碑共同组成唯一来源键。没有“任意广播”HTTP入口。未来新的重大事件可发布可信PlayerNotice，owner为空表示公告，有值表示个人通知；必须在业务事务内发布，来源键稳定且唯一。

通知与奖励、任务结果共同提交或回滚；数据库提交后才唤醒浏览器，不存在先显示再回滚的幽灵消息。战斗结算生成的通知保留到战后查看。

## 工程边界与验证入口

`avalon-chat`为独立Maven业务模块，使用角色应用接口、JdbcClient、CosId、Spring MVC SSE及现有Bearer认证。没有新增消息代理或WebSocket框架。实时连接注册表与维护调度仍限定单实例，不将该实现宣称为跨实例广播系统。

SSE同源fetch附加Bearer头，不把令牌写URL。每45秒结束连接以重新认证，15秒心跳，断线指数退避重连；ready重新读取数据库。浏览器已加载会话若断线积压超过50条，会继续分页补齐新旧消息间的缺口。

所有新实现的包契约、字段、关键步骤、权限、并发、回滚和请求生命周期均使用中文注释。

后端真实数据库验收：`ChatIntegrationTest`。架构与调度：`LayerBoundaryTest`、`MaintenanceSchedulingTest`。浏览器桌面/手机验收：`ChatBrowserIT`启动隔离服务，执行`avalon-ui/tests/chat.spec.ts`。显式设置`AVALON_CHAT_BROWSER=1`，构建最新前端后运行该测试；夹具只连接本次Testcontainers数据库。

```bash
mise exec -- ./mvnw -q -pl avalon-app -am -Dskip.frontend=true -Dtest=ChatIntegrationTest,LayerBoundaryTest,MaintenanceSchedulingTest -Dsurefire.failIfNoSpecifiedTests=false test
npm run build --prefix avalon-ui
npm run test:typecheck --prefix avalon-ui
AVALON_CHAT_BROWSER=1 mise exec -- ./mvnw -q -pl avalon-app -am -Dskip.frontend=true -Dtest=ChatBrowserIT -Dsurefire.failIfNoSpecifiedTests=false test
```
