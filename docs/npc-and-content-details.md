# 人物交互与内容详情

## 地点与人物

地点页显示在场人物的姓名、身份及任务标记。点击人物才展开介绍、现场对白、任务与服务；打开、阅读和关闭不接取、不交付、不消耗资源。人物通过稳定编号关联任务和场景行为，不按中文姓名合并。未出现人物的介绍不随地图目录下发。

| 标记 | 含义 |
| --- | --- |
| 金色 `?` | 有任务可在该人物处交付 |
| 金色 `!` | 有任务可在该人物处接取 |
| 灰色 `?` | 有已接任务，尚未满足交付条件 |
| 无标记 | 没有当前可办理的相关任务 |

同一人物优先显示可交付、可接取、进行中；面板列出全部当地相关任务，不能用追踪状态隐藏其他委托。图标具有中文无障碍名称，不只依靠颜色。远处仍显示已追踪任务的地点指引，但不能远程操作。

人物面板采用手机底部展开样式。属于人物的观察、询问和交接收进面板；没有人物承办的调查、采集和战斗保留在场景。服务分别配置到护理员、店主或导师，后端仍核验真实地点与资格。主动选择服务时先关闭人物层再跳转，浏览器返回仅关闭当前层。请求结果未知时不能关闭并丢弃课程申请。

已公开服务的锁定条件应明确展示；剧情尚未公开的服务不提前泄露。仓库、商店、恢复、研究、强化、市场和课程不通过全局按钮绕过地点。

## 内容规范

| 对象 | 描述内容 | 详情内容 |
| --- | --- | --- |
| NPC | 身份、性格和生活细节 | 介绍、当前交谈、任务、可办理服务 |
| 幻兽 | 图鉴式生态、行为与身体特征 | 物种介绍、已知个体资料、特性和技能 |
| 道具 | 用途与必要限制 | 效果、使用条件、消耗及实例绑定信息 |
| 技能 | 简明动作及效果 | 耗魔、威力、目标、冷却、持续时间与限制 |
| 特性 | 准确的战斗效果 | 触发条件、作用对象、比例与叠加限制 |

描述不把未实现的行为暗示为可操作机制。隐藏槽位遵循发现规则；不把隐藏特性写成必然更强。未来进化及剧情身份不从简介提前揭露。

道具在背包、商店、任务奖励、战后掉落与待领页面共用只读详情；技能和特性从人物或伙伴详情进入。详情采用行内展开或现有物品面板，避免反复叠加弹窗，展开后仍保留原页面位置。未获得物品可以查看已公开用途。伙伴详情展示当前物种与等级对应的整数七维，只允许读取本人持有个体。任务奖励预览只开放已可接或已进入日志的任务；多人战后物品列表只显示本人获得的奖励。

NPC介绍和服务归属维护在 `opening.json`；原形态说明维护在 `creatures.json`，进化形态说明维护在 `evolution.json` 的目标形态条目，技能说明维护在 `battle.json` 的技能条目，特性说明维护在 `ability-slots.json` 的 `abilities` 中；道具说明沿用 `items.json`，不复制第二套物品名录。正式目录由 JSON Schema 和启动引用校验约束。威力、耗魔、冷却、封印球档位及倍率等配置数值由后端生成说明，实例属性和绑定仍来自真实库存。特性及固定战斗规则变更时，必须同步核对对应说明和测试。

## 验证边界

人物面板浏览器验收使用隔离数据库、新账号和桌面／手机两种视口，覆盖打开人物不自动接取、标记变更、任务奖励预览、服务跳转、刷新及幻兽／技能／特性详情。命令权限仍由原有任务与领域集成测试验证。

当前故事开篇及诺姆分支浏览器验收均在桌面、手机两种视口通过。开篇从新账号开始；分支验收使用隔离前置夹具，覆盖改选、刷新、现场确认和完成记录，不作为自然升级证据。具体通过范围与待办统一见[实施状态](implementation-progress.md)。

`ContentDetailsTest`4项通过，包含实际配置数值、未知对象拒绝、预览不接任务及未来奖励隐藏、本人七维可读和他人个体404。测试夹具提交真实事务后再发HTTP请求。前端及浏览器测试TypeScript检查通过；这些自动化结果不替代真人手机试玩记录。
