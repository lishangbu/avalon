# 本机浏览器资源网络异常诊断

2026-10-18，完整主线浏览器路线曾记录 `ERR_ADDRESS_IN_USE` 和 `ERR_NO_BUFFER_SPACE`，Node正式接口也曾记录 `connect EADDRINUSE`。部分资源失败未阻止最终业务断言通过，不能把业务测试通过当作网络无异常。

## 可执行诊断入口

在仓库根目录执行 `rtk node scripts/diagnose-loopback.mjs 60`，需要已安装avalon-ui的Playwright依赖和浏览器。脚本仅启动临时回环HTTP服务，每轮浏览器导航加载24份模块及24份样式，同时由Node执行30次HTTP查询。任何请求失败、非200响应、数据错误或页面错误都会返回非零退出码；输出仅含固定公开路径、计数及错误，不输出凭证。不修改数据库或系统网络配置。

首次60轮通过，共4740次服务端请求、零失败；去掉每轮networkidle固定静默等待后再次60轮通过，共4740次请求、零失败，命令约3.3秒完成。第二次使用load等待模块和样式，仍保留逐轮网络失败断言。

新增实际资源模式：`rtk node scripts/diagnose-loopback.mjs 30 bundle`。从已有`avalon-ui/dist/assets`精确枚举并读取JS/CSS，浏览器通过样式及模块预加载访问真实字节，同时继续Node查询；逐份等待资源加载完成，不执行应用入口、不伪造认证或业务接口。当前构建90份资源共812573字节，30轮共3630请求、零失败，约3.1秒。资源路径只允许枚举结果的精确匹配，不开放任意文件读取。该结果依赖当时dist构建内容，不证明源码与dist一致。

## 当前结论与边界

这个入口可以捕获相同类型的资源连接错误，但目前没有触发完整主线中的故障。bundle模式已包含当时真实打包资源字节，仍不包含Spring服务端、运行中的应用逻辑、认证刷新、长时间进程状态及其他系统活动，不能用于证明这些条件无关，也不能作为修复回归通过。

此前两项纯Node简化实验各20000次请求也未复现，不能继续用类似实验的通过推断根因。当前尚未得到稳定的短复现，没有实施网络设置调整、自动写命令重试或声称已修复。下一步应将真实运行中的必要条件逐个加入此入口，只有实际复现后再比较原因与修复。
