# 主线行动与任务结算

本规则说明[开篇任务](bright-opening-design.md)中的资料、采集、照护与训练如何通过实际命令结算。多NPC、场景动作、六门学院课程及30项正式任务已接入，验证范围见[实现进度](implementation-progress.md)。命令共用角色串行锁、事务与任务回执，不引入剧情脚本语言或第二套奖励系统。

## 什么能由交谈完成

接取、听取说明、展示已有记录、接受介绍与庆祝可直接作为任务步骤。捕捉、编队、装备、恢复、战斗胜利及课程操作必须读取对应服务完成的事实，不能由“我完成了”按钮自行创建事实。

观察不再是需要点击完成的任务动作。相关信息直接显示在所在设施或NPC的资料区，按地点、人物出现条件与剧情前置筛选；阅读、刷新和展开说明均不写事实、回执或奖励。纯信息步骤在原地通过一次任务交谈确认，选择、战斗、采集、交付仍核验实际行动。

## 有限的场景动作

| 类型 | 开篇实例 | 输入与完成条件 | 重复行为 |
| --- | --- | --- | --- |
| COLLECT_TASK | 采集不破坏巢穴的庆典散石 | 服务端配置物品与数量；满足任务前置且到达领取点 | 已领取只展示结果；关键物丢失需按收据恢复而非增发可售品 |
| CARE | 小站照料驮兽 | 驮兽现况和水源说明直接提供，实际交接照护用品 | 状态逐步保存，重试不重复消耗，任务完成后只闲聊 |
| PRESENT_RECORD | 学院调查报告 | 依据公开资料及实际战斗/到达事实，选择与记录相符的方案 | 答错可重看记录，不清空探索成果 |

只添加当前任务实际使用的动作。场景动作不接受客户端给出的物品、数量、奖励、成功事实或地点；所有效果由启动期内容定义。未知actionId、越地点、未开放或不符合步骤的请求明确拒绝。

## 与任务事务的关系

### 人物身份与接待资格

QuestCatalog使用启动内容中的NPC名录与地点接待绑定：名录包含稳定id和name；地点绑定包含npcId及可选出现/离开事实；任务步骤引用npcId，显示名从名录取得。非环境任务必须提供npcId，任务和地点均不接受独立姓名字段，不能使用任意名字绕过身份验证。

同一地点可以有多个接待者。不同地点可以有同一人物的分阶段绑定，但不能在相同个人进度中同时呈现互斥位置；常驻机构服务不随人物离开而消失。人物移动尚不需要自由寻路、日程或全服位置状态。

命令层除原有任务前置与人物所在地外，还验证接待绑定当前可见。任务列表可以显示接待目标方向，但不能在人物缺席时提交；回看对白读取历史展示文本，不等于当前NPC在场，不发奖。不可把前端隐藏当作唯一资格校验。

启动校验覆盖未知NPC、重复名录ID、同地点重复绑定、未知事实引用与步骤找不到接待绑定。相同中文名不能充当身份；纯环境资料直接显示在地点，不为石头、水源和路标捏造NPC。

开篇名录包含阿德、布鲁诺、梅莎、特林、克林、费恩、米菈及商人、看护人、引路人。具体任务绑定以正式任务与地图目录为准，学院可以同时接待三名人物。名录、Schema、目录校验、读投影和前端显示使用同一套稳定编号。

纯环境任务显式声明`environmental: true`，不配置`npcId`，也不允许`onArrival: true`。资料步骤允许没有行动事实，但仍须接取并在原地明确确认；含行动目标的步骤必须核验场景、正式战斗、训练、准备或到访结果。BQ026直接整理城郊资料，BQ027仍要求实际清路与战斗胜利，不需要把导师临时派来接待。该模式不为普通人物任务放宽接待检查。

### 提交与重试

动作请求采用requestId与角色位置版本。先锁角色、验证请求归属；已有同负载回执直接重放，不因之后移动而重新执行。新请求验证位置与动作前置，同一事务提交必要物品变动和动作回执。相同requestId不同负载拒绝。重复完成同一一次性动作不叠加奖励。

任务步骤继续使用已有任务完成命令，读取上述动作回执或派生事实。执行动作成功不自动跨过后续交谈或旅行节点；只有明确写成同一现场步骤的完成才能在一次事务内结算任务奖。

失败整体回滚，客户端超时后查询或重试同一请求。位置已变化时不能靠旧页面执行远程照护；任务奖励满包进入既有待领通道，不撤销已经完成的实际行动。正式采集物与临时教学库存不可混用。

## 开篇绑定清单

| 任务 | 必需的行动证据 | 不足以通过的行为 |
| --- | --- | --- |
| BQ004 | 结契回执、个体及初始装备的原子交付 | 只读了梅莎的介绍 |
| BQ005 | 当前有效出战名单、合法穿戴与技能查看记录 | 打开编队后未保存 |
| BQ006 | 接取后在河岸确认资料 | 仅远程查看任务列表 |
| BQ007 | 接取后真实捕获来源、本人所有个体的登记事实 | 交易买到或只击败目标 |
| BQ008 | 巢外散石的任务物领取与上交 | 消耗幻兽或普通制作石料 |
| BQ009 | 一次性补给收据、正式恢复动作、合法名单 | 仅打开商店、已有满血但未接受检查 |
| BQ010～011 | 林口资料直接确认；洞口由真实开战记录准备 | 不能远程确认或用读资料代替开战 |
| BQ012 | 指定首领正式胜利结算 | 进入战斗、撤退或训练胜利 |
| BQ015～016 | 对应旅行到达与照护事件，以开篇逐项目标为准 | 仅背包出现饲料 |
| BQ018～023 | 每课各自隔离会话的通过回执 | 临时个体仍在仓库或只看教程 |
| BQ024 | 所有指定课程回执的交集 | 重复同一课五次 |
| BQ027～028 | 清路动作、正式战斗胜利与报告选择 | 只读资料、未打赢任务战斗 |

捕获来源与永久任务完成事实分开。已经合法登记并完成的教学任务不因后来放归伙伴而倒退；未登记时丢失个体需按任务明确目标处理，不以隐式重新发宠补偿。

## 临时训练边界

训练会话保存正式入场名单引用与临时快照，调用相同战斗、技能学习和物品校验规则，但通过训练上下文选择临时仓储。这里快照是战斗隔离数据，不是内容热更新版本。

临时装备、技能书、球、金币和幻兽不进入真实资产表，不允许出售、交易、放归返还或带出；训练回执只给一次性课程完成事实。永久职业技能与正式奖励必须在通过后的正式事务中分别交付，并验证职业匹配。

掉线可继续同一训练或主动退出重开。退出与失败丢弃临时变化，不把训练后状态复制回真实角色。进入后禁止真实队伍和库存的并行变更；解除会话锁和清理临时库存必须随结束原子完成。

## 必须通过的实现验收

两个浏览器同时完成同一动作只领取一次；复制他人actionId不能越过地点和前置；旧位置版本不能远程提交；重试与事务回滚不重复资源。资料反复读取不改变角色、任务目标或资产。满包、零金币、训练断线、课程并行汇合、先完成不同课程以及返回家乡都具有明确可达路径。

实现测试必须调用正式服务或HTTP接口，不另写Python模拟任务引擎证明通过。`SceneActionIntegrationTest`覆盖并发采集、事务回滚、错答纠正、位置和请求校验、环境任务事实及一次性结算；内容校验、NPC与学院专项回归通过。场景动作缺少生产者时启动校验直接失败；这些测试不替代新号全流程、满包与零资源路线或真实浏览器验收。

## 资料与到访目标

`scene-actions.json` 的 `actions` 只定义实际操作，`information` 定义设施或NPC资料，不接受命令执行。旧观察ID不能作为新的场景动作执行，也不得被任务、动作或地图当作完成事实引用；历史回执与已完成任务保留。

航行中的必经地点使用 `VISIT:<地点ID>`。移动事务自动发布到访事件，只给已接取、已满足步骤前置的当前目标记里程。读地图、读取资料和出发前的历史到访不能补算。BQ063要求实际经过两个航标和近岸湾，BQ065要求当前返程阶段重新经过两个航标；可以提前返港恢复，但不能用捷径替代整段行程。
