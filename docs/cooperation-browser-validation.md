# 合作交易与制造页面验证

2026-09-24。使用隔离 PostgreSQL 与真实打包服务，桌面及手机视口执行同一组 Playwright 用例；没有实体手机参与。

## 流程与夹具边界

主流程由两个独立浏览器会话完成，另外两个账号用于金币不足、满背包和挂单失效验证。夹具预置11级人物、已完成剧情、生活专业、伙伴、工具及资金；采矿者预置2级采矿。制造所用碎石必须由页面在线派遣实际取得，不注入原料，不模拟业务响应，也不跳过正式移动与设施条件。

采矿者在诺姆矿场外庭完成两轮采集取得4份碎石，停止派遣后经地图前往诺姆城商店，合并上架3份。购买者通过市场页面购入，前往诺姆锻造坊，用这3份碎石制造1件木级部件。重新加载页面核对库存与金币：卖方剩1份碎石、收入5金币，买方花费6金币、原料耗尽、获得1件部件，税费1金币。

这条流程用于验证跨账号页面、认证、持久化与扣费衔接，不代表高级装备的完整投入测量或真人操作时长；高级装备服务端链和288来源材料页面测试保持原有验证范围。

## 异常与修复

- 金币不足及背包满：从页面尝试购买，检查错误提示，前后对比金币与完整背包，确认失败没有扣款或交付。
- 挂单被买走：保留另一个账号打开的详情，待购买者成交后再次购买，检查结束提示与购买入口移除。
- 制造重复点击：暂停真实成功响应，连续触发制造操作，确认只发出一次制造请求，产出与熟练度只增加一次。
- 全部工具报废：JUnit 控制报废抽签，使用最后一把工具批量制造；当前件完成后截断，剩余材料保留，重放不重复产出，用失效工具新请求也不扣料。
- 既有真实事务测试继续覆盖满背包制造回滚、部分批次完成后空间耗尽、备用预算、市场竞争与幂等。

修复市场失败后仍保留旧详情的问题：写操作失败也刷新查询；购买失败后复核详情，更新剩余量或移除已结束挂单的购买入口，保留原失败原因。同时清除上一次操作的成功提示，并在忙碌时阻止再次提交修改待重试请求。

## 复验入口

使用现有 Maven/JUnit 和 Playwright，不新增包装脚本：

```bash
mise exec -- ./mvnw -q -pl avalon-app -am -DskipTests package
AVALON_LIFE_BROWSER=1 PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/google-chrome ./mvnw -q -pl avalon-app -am -Dskip.frontend=true -Dtest=LifeSkillsBrowserIT,LifeCraftingFlowTest,MarketListingTest -Dsurefire.failIfNoSpecifiedTests=false test
```

`PLAYWRIGHT_CHROMIUM_EXECUTABLE`按本机浏览器位置设置，使用 Playwright 管理的 Chromium 时可以省略。运行证据归档于`outputs/cooperation-browser/`。

只复验合作用例时，在测试命令添加 `-Davalon.life.browser.grep=双账号`，由原生 Playwright `--grep`筛选；不重跑已通过的钓鱼等耗时用例。
