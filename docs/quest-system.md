# 任务系统规则

本文规定任务的分类、生命周期和进度归属；具体剧情、目标与奖励由正式任务内容定义。实现与验证范围见[任务系统验收](quest-system-validation.md)，整体游戏进度见[开发进度](implementation-progress.md)。

## 分类与标签

任务类型为主线或支线。主线承载必要剧情与区域推进；支线提供可选故事和玩法。不能仅凭编号前缀、名称或奖励推断任务类型。

任务可以引用多个标签。首批标签为引导、探索、收集、挑战、副本；标签在内容目录统一定义，任务引用稳定编号，启动时校验引用与重复值。标签用于展示和筛选，不决定接取、奖励、重复或放弃规则。

引导不是第三类任务。必经教学可以是带引导标签的主线，可选教学可以是带引导标签的支线。所有一次性任务完成后统一进入已完成记录，不为引导任务另设归档机制。

框架的实例、计数、周期、限时、分支及扩展接口见 [任务框架实现约定](quest-framework.md)。下述前15级内容仍使用一次性规则；通用运行规则以框架约定为准。

## 重复与放弃

任务以角色为进度主体。前15级使用 `repeatPolicy: ONCE`，表示每角色只能完成一次，不表示一生只能点击一次接取按钮。

- 未接取时，满足前置和接取地点要求即可接取。
- 进行中不能创建第二份相同任务；重试不能重复发补给。
- 已完成后不能重新接取；交付请求重试只能恢复原结果，不能重新执行奖励。
- 主线 `abandonable: false`；支线默认允许放弃，也可按具体内容禁止。
- 放弃保留当前步骤和已完成目标；重接从保留位置继续，放弃期间不累计新的任务专属进度。
- 放弃不退回已消耗的物品，不重复发接取补给，也不撤销已解锁功能、地点等永久事实。
- 必需补给必须有补领或其他获得途径。补领只补足继续任务所需的缺口，不能借放弃、重接或重复请求无限获得补给。

`repeatPolicy` 与 `abandonable` 分别控制完成后的重复和进行中的退出，不能互相代替。每日与循环任务不在前15级本次范围内。

## 接取与进度

普通任务先主动接取，再记录击败、捕捉等任务目标。已探索地点、已解锁功能等永久事实可以认可已有记录。提交物品允许使用已有库存，但必须由玩家确认消耗。

目标应明确读取永久事实还是任务有效期间的行为记录。不能直接把所有历史战果当作新接任务的完成条件，也不能把永久事实当作放弃时应删除的任务数据。

同一行为可以推进多个符合条件的进行中任务。一次战斗、捕捉或照护无需强制归属于唯一任务；需要消耗的物品或上交的幻兽则只能实际扣除一次，不能供多个任务重复抵扣。

任务、步骤、目标分别表达故事单元、行动顺序与具体要求；不强制每项任务具有固定步骤数量，也不为每次点击创建独立任务。

## 达成与交付

区分目标达成与完成领奖。NPC委托通常到指定人物处交付；现场探索任务可在指定现场确认完成。交付方式由任务定义，不要求所有任务返回最初接取地点，也不提供远程交付或任务传送。

清理、照护等已完成事实在战斗失败后保留；失败的当前战斗需重试。临时战斗状态的重置不能删除长期任务进度。

交付重新校验角色、地点、目标与库存；消耗、奖励、任务完成及结果回执在同一事务提交。并发交付或网络重试不能重复扣物品、上交幻兽或发奖励。背包不足沿用待领规则，不应导致任务物品丢失。

## 组队归属

现场参与者可共享团队战果，但各自必须满足自己的任务条件。接受邀请、加入队伍或成员远程获胜本身不授予任务进度。

对话、调查、提交和领奖分别操作；捕捉仅计入实际获得幻兽的玩家。团队战果的参与资格以战斗系统实际参战记录为依据，不能仅检查结算时队伍成员列表。

## 等级、列表与追踪

默认显示推荐等级，通过剧情前置控制解锁；确有玩法要求时再设置最低等级，例如进化教学。不能给每项任务机械叠加等级锁。

支线接取数量不限，不设置50条等隐性未完成上限。请求防重、限流与分页属于工程措施，不改变正常接取规则。

任务列表按主线、支线组织，可按标签与地点筛选。最多同时突出一条主线和一条自选支线；追踪只影响指引显示，不暂停其他任务的进度。已完成任务不再出现在进行中待办，保留可查看的记录。

追踪偏好按角色保存，刷新或重新登录后保留。从未设置偏好时默认显示第一项可用主线；显式取消后不自动恢复。完成、放弃的任务不再显示为追踪中。地图对每项追踪任务只突出一个下一步，同时保留当前地点其他可接取、可交付的任务入口；追踪不是访问现场任务的门禁。

当前行动指引应指向下一项实际动作的地点，不能始终显示最终交付地点。移动仍遵守地图相邻道路；任务追踪不产生自动传送。

## 阶段对白与世界反馈

任务状态标签保持清晰，世界观由具体任务的阶段对白、现场描述和完成后的反馈承载，不用统一的诗化标签代替内容。现有66个步骤已配置阶段对白并接入现场交谈，交付条件由查询与命令共用的规则判定。

| 场景 | 文案职责 |
| --- | --- |
| 可接取、尚未接取 | 交代人物处境、委托缘由和请求，让玩家理解为什么要做 |
| 接取时 | NPC回应玩家的承诺，给出必要线索和约定 |
| 进行中、目标未达成 | 回应已有进展，提醒尚缺的行动；不同关键步骤可有不同对白 |
| 目标达成、尚未交付 | 表达准备验收的期待，不提前宣布奖励已发放或事件已解决 |
| 成功交付 | 展示解决问题的当场反应和后续影响，与完成事务结果一致 |
| 完成后再访 | NPC记得玩家的帮助，展示日常变化，不再次索要已交物品或重演首次领奖 |
| 放弃后重接 | 承认既有进展并恢复委托，不重复首次补给叙事 |

“任务中”与“任务未完成”不是两个并列生命周期状态：进行中按当前目标和进展选择对白；“任务后”则区分刚刚交付与日后再访。暂不可接取的任务不展示未来剧情。无需为瞬时对话任务强造一个进行中阶段。

阶段对白放在后端正式任务内容中，引用已有NPC与任务步骤，由服务端依据真实状态选择。阅读对白不推进任务、不领取奖励；接取、提交与消耗仍须明确操作。已完成命令的幂等回执和再访对白是不同用途，不能为了换对白重新执行完成命令。

地点页用人物姓名旁的金色问号、金色感叹号、灰色问号区分可交付、可接取与进行中任务，优先级依次递减。点击人物后查看对应对白、任务与服务；现场环境行动保留独立入口。任务物品奖励可在接取前展开用途说明，只允许查询已出现的任务，不泄露后续奖励。具体交互见[人物交互与内容详情](npc-and-content-details.md)。

每段优先用一至三句体现NPC性格、当地生活或幻兽习性，并保留明确行动线索。以温馨日常为主，重要事件再提高情绪强度。任务记录保留简明目标与已发生事件，不提前展开后续剧情；NPC现场交谈呈现完整对白。完成后的反馈只反映该角色的经历，不自动修改所有玩家共享的世界状态。

## 验收要求

- 普通任务接取前的历史击败不能误算；永久解锁和合法已有库存仍可认可。
- 放弃、重接、断线、刷新保留约定进度；放弃期间的战斗不补记专属目标。
- 完成后重新接取被拒绝；并发、换请求号及原请求重试均不能重复发奖或补给。
- 一次行为可以推进多个任务；同一份交付物不能重复消耗或重复抵扣。
- 组队参战者、远程成员、未接任务成员和捕获者分别按资格计数。
- 标签变更不改变玩法规则；未知标签、无效前置及不可达的接取与交付配置必须被校验发现。
- 已完成记录、筛选、追踪及下一步地点在手机与桌面页面均可操作；刷新后保持一致。

## 实现约定

现有 `QuestCatalog` 使用步骤、前置与事实配置，`QuestCommandService` 已有角色级步骤回执和事务奖励。`QuestAcceptCommandService` 已扩展到所有任务步骤：首次接取创建整项任务参与状态，后续步骤按配置领取一次性补给，放弃后可在可用步骤地点重接。交付要求整项任务处于进行中，所有步骤完成后关闭参与状态。

任务规则目录已提供类型、多标签、一次性策略及启动校验；任务记录读模型和页面已按整项任务聚合，支持标签、地点筛选及完成记录。整项任务的所有步骤完成才归档，包括并行学院课程，不能仅凭某一步的完成标记提前归档。现有13组任务均有主线前置依赖，暂保留为主线，不能按编号猜测支线。

放弃命令读取任务规则并核验状态版本，保留现有步骤回执，重接不重复发首次补给；任务记录展示参与状态及符合规则的放弃操作。当前正式13组任务均为主线，支线放弃通过独立测试内容验证。

任务期间目标已独立存入 `quest_objective`：真实行为在原事务中同步发布，只有已接取、未完成且步骤前置已满足的任务记录目标。接取前和放弃期间的历史事实不补算；重接保留已有有效目标。掌握界面操作及已学技能仍可读取永久事实。查询和交付共用目标判定，重复命令回执不产生新行为。BQ007同时要求任务期间实际捕获和回中心登记，重放旧捕获来源不能补进度。

任务专属场景及中间动作按有效接取状态开放，已完成动作回看不再发物品或补计目标。场景目录启动时核对任务、场景和道路的正向解锁可达性；消耗交付场景不能作为多个步骤的同一专属目标，共享实际行动则允许推进多个任务。

步骤可通过 `acceptance.location` 与 `acceptance.npcId` 指定独立接取入口，省略时使用交付入口。BQ057在罗温杂货铺接取、温蒂妮城交付；读取与写命令共用当前入口判定，接取不移动角色。任务记录只返回已完成及已开启步骤的标题与地点，后续步骤仅计入总数。

`quest_tracking` 已保存主线、支线槽位和状态版本，接口为 `GET/PUT /api/quests/tracking`。写命令验证角色身份、任务分类和可见状态，不接受未来、已完成或已放弃任务。任务页支持切换、取消，地图使用相同偏好。真实数据库覆盖并发重试、旧版本拒绝、原事务回滚、角色隔离，以及一次真实行为推进两条已接取任务；桌面和手机浏览器验证切换、取消、刷新恢复和地图指引。

`quest-dialogues.json` 为66个正式步骤提供接取前、接取回应、进行中、待交付、再访与重接文案，交付回应沿用步骤的 `dialogue`。JSON Schema及目录交叉校验拒绝缺项、额外步骤和空白文案。`GET /api/quests/dialogues` 只返回当前地点可见人物的当前交谈；服务端选择阶段，完成后无新委托时显示该人物最近步骤的再访。地图可展开阅读，接取与交付仍需明确操作。真实数据库验证阅读不改状态或奖励、角色隔离、阶段切换、重接和原回执重放；罗温线桌面与手机浏览器验证展开及接取后文本变化。

`QuestDeliveryRequirements` 已统一任务投影与交付命令的即时库存、出战人数和指定伙伴位置检查。待领库存不计入可交付数量，同物品的多项消耗累计判断；缺少条件时对白保持进行中，命令在角色锁内复核。真实数据库验证缺物品拒绝、补齐后待交付、消耗与奖励回滚及重试一次生效；编队专项验证替补不冒充出战、指定来源与位置必须满足。

学院后续课程要求前置课程已经交付，不能仅凭训练结束事实提前开放。前端交付成功后使相关查询失效，及时刷新课程、商店、地图及任务入口。副本胜利只为奖励事件中确认的实际参与者发布战果，仍由每名角色自己的任务状态决定是否记入目标。

捕捉补给耗尽后可通过已开放的普通野战获得金币并购买封印球，不要求先完成捕获登记。任务消耗以角色锁内的即时库存为准，同一份物品不能抵扣两份任务。调整前置时须保证可选支线不意外成为必经门槛，并重新验证完整旅程与经验来源。

## 资料不计为观察目标

设施或NPC资料直接展示，不要求点击观察、读完打勾或生成观察事实。纯资料步骤仍需在原地接取和明确交谈确认；实际选择、战斗与交付仍按正式目标结算。场景操作目录不再支持 `OBSERVE`。航行的必经地点由真实移动自动产生 `VISIT:<地点ID>`，按当前任务阶段登记，历史到访不能代替当前返程。
